# Normas de Clean Code

1. Usar nombres claros que expresen intencion.
2. Mantener una responsabilidad principal por clase.
3. Mantener metodos pequenos y concretos.
4. Evitar duplicacion de reglas de negocio.
5. Mantener atributos encapsulados.
6. Separar UI, Controller, Service, Repository y Model.
7. Validar entradas en la capa correspondiente.
8. Evitar comentarios que solo repitan el codigo.
9. Evitar numeros y textos magicos; usar constantes con significado.
10. Manejar errores explicitamente; no ocultar excepciones.
11. Evitar acoplamiento innecesario entre modulos.
12. Antes de integrar, comprobar compilacion, contratos, pruebas y responsabilidades.
13. Usar mensajes de commit descriptivos y, preferiblemente, Conventional Commits.
